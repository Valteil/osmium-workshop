## Platform

web

## Users

Two equally weighted primaries, both working locally on their own machines:

- **Hobbyist AI-image creators** — ComfyUI users curating training datasets (typically
  LoRA/LoCon) from their own generated images. Solo, privacy-conscious, want a fast
  all-in-one tool instead of a node graph.
- **Pro dataset wranglers** — people managing large, large-source datasets (including
  commissioned/single-subject datasets) who need bulk operations, auditability, and
  repeatability at scale.

Success for both: caption/tag data that's clean enough to train on, with every edit
logged, confirmed, and undoable.

## Product Purpose

Osmium Workshop is a **local-first dataset tag editor** for AI training images
(`image` + matching `.txt` caption files). It exists because curating thousands of
image/caption pairs is tedious and ComfyUI alone offers no dataset management. It is a
feature-heavy, ComfyUI-compatible dataset manager: tag editing as clean
space-separated text (underscores normalized on load, restored on save), plus
dataset-wide manipulation tools, automation (WD14 autotagging, Retroactive
Merge/Void rules, bulk passes), SynthDat synthetic data generation, and direct sync
with ComfyUI's output folder. Portable Electron app — unzip, run, nothing installed.

## Positioning

All-in-one dataset processor for the "slop pipeline": generation and dataset curation
in one loop. A neighboring tool (a plain tag editor, or ComfyUI itself) could not
truthfully copy the combination of undo-able edit logging, retroactive rule-based tag
correction, per-image lockdown/exemption semantics, on-device or network WD14
tagging, and direct ComfyUI output syncing — all offline, portable, in one binary.

## Operating Context

- Local folders of image + `.txt` pairs are the unit of work; the app writes a few of
  its own metadata files into the dataset folder (`Disabled/`, `_tag_edit_log.json`,
  `_dts_canonical_tags.json`, `_dts_meta.json`) without touching images/captions
  unless explicitly instructed.
- ComfyUI may be present on the same machine (desktop) or over LAN/Tailscale
  (mobile/Comfy Bridge) for generation and network tagging; WD14 can also run fully
  on-device (models download on first use).
- Settings, themes, achievements live in `data/` next to the executable — portable,
  resettable, carryable.
- Dense, keyboard+mouse power-tool workflow on desktop; the in-app ❓ Help mirrors the
  USER_GUIDE.

## Capabilities and Constraints

- Views: Grid (default, masonry option), Compact (hover previews, side-by-side
  comparison), Single (compact preview + full-size lightbox, Tag Sorting), Disabled
  quarantine, Originals (pre-bucketing images). Rotate/crop with undo in the image modal.
- Editing: tag chips, filter sidebar with AND/OR/XOR/NOT and keyword families, saved
  per-dataset edit log with full undo/redo and file-level revert.
- Power tools: Tag Pruner (Unify/Void), Retroactive Merge/Void rules with immune/
  exempt images, Master Tag Control (bulk apply/rename/delete), Tag Overseer
  (sequential tagging, WD14 settings), SynthDat Overseer (ComfyUI generation).
- Destructive actions (delete permanently, rename all, bulk ops) are confirm-modal
  gated, logged, and undoable where possible; "delete permanently" is undoable never.
- Naming and tags use Danbooru-style conventions; tags surface as wiki-linked terms.
- Technical: Electron + TypeScript, `main.js`/`preload.js`/`renderer/app.js` are
  generated by the build (`npm run build`), dev loop `npm run refresh-app`. Windows
  portable packaging; Electron-only (Tauri port discontinued). Theme system with a
  shop/achievements economy that gates alternate looks.
- Deliberately undecided product facts: none named at init time.

## Product Principles

1. **Nothing destroys work silently.** Every edit is confirmed where destructive,
   logged, and undoable; users must be able to back out of any layer of bulk change.
2. **Local-first and portable.** The user's files and settings stay on their machine;
   no installer, no cloud, network is opt-in per feature.
3. **Power without station-wagon complexity.** Deep bulk/automation features that
   stay approachable, with in-app help and plain-language tag editing.
4. **Respect the dataset as a file system.** The app is a careful guest in the user's
   folders; metadata is additive, images and captions are only touched on explicit
   instruction.
